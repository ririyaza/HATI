# HATI

**Helping Anxiety Through Immersion** — a mobile, emotion-aware, gamified virtual companion for students with high social anxiety symptoms.

HATI is a Flutter app (Android-first) built as an undergraduate thesis project. Students meet **Hati**, a frog companion, take a short social anxiety screening (SPIN), and then practice everyday social situations through interactive, voice-driven scenarios. During each scenario, a backend model detects the emotion in the student's spoken answers and Hati responds with coaching and coping strategies.

> HATI is a self-help and practice tool. It is **not** a diagnostic instrument or a substitute for professional care.

---

## Features

- **Onboarding** – consent flow, profile setup, and a guided tutorial.
- **SPIN assessment** – the 17-item Social Phobia Inventory, scored and broken down by theme. Results decide which modules are recommended first.
- **Themed scenario modules** – six immersive scenarios, each with an Easy and a Hard mode:

  | Scenario | Theme |
  |---|---|
  | The Professor's Request | Fear of Authority |
  | The Food Hall's Seat | Fear of Strangers & New People |
  | Project Defense: Defended or Offended | Fear of Being Observed & Performing |
  | The Student Gathering: To Approach or Not? | Fear of Social Gatherings |
  | The Group Project: Defending Your Work | Fear of Negative Evaluation & Embarrassment |
  | The Jeep Stop: Hiding Visible Anxiety | Physiological Symptoms |

- **Emotion detection** – spoken answers are recorded and sent to the HATI backend, which classifies the emotion and drives the next step of the scenario.
- **Hati Chat** – a conversational companion powered by Gemini through Firebase AI Logic.
- **Progress & reassessment** – a 2-week SPIN + GAD-7 check-in, weekly progress, scenario history, and emotion summaries.
- **Gamification** – modes completed, levels, day streaks, and badges.
- **Support resources** – help center and contacts for professional support.
- **Notifications** – daily check-in reminders.
- **Audio** – background music, sound effects, and Hati's voice cues, with in-app volume settings.
- **Offline handling** – connectivity banner and queued saves when the device is offline.
- **Admin inbox** – an admin view for messages sent from the app.

## Tech stack

| Layer | Technology |
|---|---|
| App | Flutter (Dart SDK `^3.11`), Provider |
| Animation | Rive (Hati's moods), Flame |
| Auth | Firebase Authentication (email/password, Google, Facebook) |
| Data | Cloud Firestore, Firebase Storage |
| AI chat | Firebase AI Logic (Gemini) |
| App integrity | Firebase App Check |
| Emotion detection | Python backend on Azure Container Apps (separate repository) |

## Getting started

### Prerequisites

- [Flutter](https://docs.flutter.dev/get-started/install) **3.41** or newer (stable channel)
- Android Studio with an Android SDK, plus an emulator or a physical device
- Access to the HATI Firebase project (ask a project maintainer)

### Setup

```bash
git clone https://github.com/ririyaza/HATI.git
cd HATI/app
flutter pub get
flutter run
```

The Firebase configuration (`lib/firebase_options.dart` and `android/app/google-services.json`) is already included in the repository. To point the app at a different Firebase project, regenerate both with the [FlutterFire CLI](https://firebase.google.com/docs/flutter/setup):

```bash
flutterfire configure
```

### Backend

Scenario emotion detection calls the HATI backend. Its URL is set in `ScenarioApi.baseUrl` in
`lib/features/emotiondetection/themed_scenario/api/scenario_api.dart`.

The backend runs on Azure Container Apps and scales to zero when idle, so the **first scenario request after a quiet period can take up to about a minute** while the server starts.

### Firestore rules and indexes

```bash
firebase deploy --only firestore:rules,firestore:indexes
```

## Running tests

```bash
flutter test
```

## Building a release

```bash
flutter build apk --release        # APK for sideloading
flutter build appbundle --release  # AAB for the Play Store
```

Release signing needs `android/key.properties` and the upload keystore. Neither is committed to the repository (both are git-ignored), so get them from a maintainer.
